# Usability review — 0.1.0-rc.1 (2026-09-16)

What was done, what it found, what changed. Nothing here is a user study: no one but the
maintainer has used the app, and none of it was run on a phone. It is the most honest review that
can be done from a headless environment — rendered screens read by eye, and the code walked against
the usual heuristics — and it is recorded so the first real device pass (docs/RELEASE.md §9) starts
from a known list rather than from scratch.

## 1. Method

1. **Screenshots.** The headless desktop UI suite renders every screen on the real content packs
   (`composeApp/src/desktopTest/.../ScreenshotTest.kt`): 15 screens × light/dark × phone (412×915)
   / desktop (1280×800) = 60 images, reviewed one by one, then the same screens under a forced
   right-to-left layout direction and at 2× font scale (added in this pass, D-29). A curated set is
   in [`screenshots/`](screenshots/); the full matrix is regenerated by
   `./gradlew :composeApp:desktopTest --tests '*ScreenshotTest*'` into `build/ui-shots/`.
2. **Heuristic walkthrough.** Every screen, the store and all user-facing strings were read against
   Nielsen's ten heuristics plus the lenses that matter for this product: first run, empty and
   blocked states, error recovery, feedback, navigation and discoverability, copy (jargon and the
   D-18 honesty rules), one-handed phone ergonomics, consistency, contrast and motion, and
   performance as experienced (work done on the UI thread or on every recomposition).
3. **Automated checks** added so the findings stay fixed: an accessibility audit test (every
   clickable node has a label or role and a ≥ 48 dp target) and RTL / 2× smoke tests for every
   screen.

Severity: **Blocker** stops or misleads a first-time user; **Major** costs them an action or a fact
on a common path; **Minor** is friction; **Polish** is taste.

## 2. Findings

Status: **fixed** = in 0.1.0-rc.1 (this pass); **open** = recorded for a follow-up, with the
reason; **withdrawn** = looked like a problem in the screenshots and was not.

## 3. What works (do not break)

- The first session is close: four intro taps → picker → *Begin* → tap the pool. Back (gesture,
  key or button) steps back through onboarding, the check, a session, the colophon and secondary
  views instead of exiting; a cancelled swipe is a no-op.
- Every blocked or empty state names a reason **and** a next action (all languages resting → a
  Languages button; no texts → the import buttons beside the note; no primer → "Open the comic";
  hypothesis panels → "not enough data yet, need at least 20 in each group").
- Grades never rely on colour alone (✓/✗ glyphs, dashed underline + ", new to you"; lane dots
  always paired with a name), and reduced motion is a real path end to end.
- The honesty rules hold: no user-facing string contains the forbidden vocabulary; the only score
  is always labelled as the share of a language's bubbles readable unaided.
- Provenance discipline: one play control, never two, always labelled recording · source · licence
  · author or "synthetic voice"; NC/ND filtered; HTTPS-only with per-hop checks and byte caps.
- The visual system reads calmly in both themes on both form factors; the session view in
  particular (crop, tokens, explanation, translation, options) is clear and well paced.

## 4. Open questions for the maintainer

1. **"Days you showed up"** is a cumulative count of distinct active days. It is not a streak, but
   it is a number people protect. Inside or outside D-15?
2. **The baseline checks** — 48 items each, "three minutes per language", nine default lanes —
   add up to about half an hour before the first fully honest session. Push one check inline in
   onboarding, or start with fewer default lanes?
3. **Cosmos and assistive technology.** The field is decorative for screen readers by design; the
   word card and exact-match search are the carriers. Is a list view needed?
4. **Contrast on the card colour.** Secondary text on cards was 4.39:1 (now raised). If the
   "deliberately low-contrast material" look is a hard requirement, say so and the tokens can be
   revisited with that constraint written down.

## 5. Not covered

Real devices and real people: TalkBack traversal order and announcements, the predictive-back
preview, edge-to-edge insets under gesture navigation, Arabic line height on API 36, 200 % text on
a physical 6" screen, one-handed reach measured rather than estimated, and a first-time user's
comprehension of the copy. Those are the docs/RELEASE.md §9 pass.
